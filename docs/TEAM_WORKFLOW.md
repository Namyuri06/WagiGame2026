# 팀 협업 및 코드 규칙

## 역할 분담

- **파트 1 · 플레이어/성장 (박지윤):** 비둘기 이동·애니메이션, 음식 획득과 체력·이동 속도·스킬 파워 성장, 눈빛 공격
- **파트 2 · 군단/AI (남유리):** 동료 비둘기와 군단 버프, 인간 빌런 이동 및 FOV, 세뇌와 상납 상태 머신
- **파트 3 · 전투/레벨 (진자연):** 응가 폭격과 철벽 인간 전투 규칙, Stage 1~3 맵과 동선
- **파트 4 · UI/통합 (이우진):** HUD와 미니맵, 사운드·이펙트 매니저, 파트 간 UI 연결

각 파트는 위 표의 코드·에셋 영역을 우선 소유합니다. 공용 코드, 공용 데이터 형식, 다른 파트의 프리팹을 변경해야 할 때는 먼저 담당자와 인터페이스를 합의하고 PR에 변경점을 적습니다.

## 팀원 브랜치

각 팀원은 본인 이름을 사용한 장기 브랜치를 직접 만듭니다(예: `team/<이름>`). 팀원 브랜치는 프로젝트 완료 전까지 유지하며, PR을 `main`에 병합한 뒤에도 삭제하지 않습니다. `main`에 직접 커밋하지 말고, 각 작업 단위가 끝나면 본인 브랜치에서 `main`으로 Pull Request를 엽니다. 작업을 시작하거나 병합한 뒤에는 최신 `main`을 본인 브랜치에 반영합니다.

## 공통 데이터 이름

기획 단계에서 정한 핵심 값은 아래 이름을 유지합니다.

| 의미 | 식별자 | 형식 |
| --- | --- | --- |
| 플레이어 체력 | `playerHp` | `float` |
| 동료 비둘기 수 | `minionCount` | `int` |
| 포섭한 인간 수 | `bribedHumanCount` | `int` |
| 눈빛 공격 대기 시간 | `eyeAttackCooldown` | `float` |

새 시스템은 소유 파트와 공개 인터페이스를 정하고, 다른 파트가 내부 구현에 직접 의존하지 않도록 합니다. 음식 정보와 스테이지·적 스펙은 `Assets/_Project/Data/`의 ScriptableObject로 관리합니다.

## UI 갱신과 이벤트

게임 상태를 바꾸는 시스템은 상태 변경 시점에 C# `Action` 이벤트를 발생시킵니다. UI는 필요한 이벤트를 구독해 표시를 갱신하고, 파괴되거나 비활성화될 때 구독을 해제합니다. UI가 플레이어·적 스크립트의 내부 변수를 매 프레임 직접 읽는 방식은 피합니다.

## 코드와 에셋

- C# 타입과 메서드는 `PascalCase`, 로컬 변수와 매개변수는 `camelCase`를 사용합니다. 공통 기획 식별자는 위 표를 우선합니다.
- 파일 하나당 주요 `MonoBehaviour` 또는 데이터 타입 하나를 두고 파일명과 타입명을 맞춥니다.
- 스크립트는 `Assets/_Project/Scripts/`의 기능별 폴더에, 공유 가능한 밸런스 데이터는 `Data/`에 둡니다.
- Unity가 만든 `.meta` 파일을 원본 에셋과 함께 커밋합니다. 에셋 이동은 파일 시스템에서 직접 이동하지 말고 Unity 에디터에서 합니다.
- Pull Request는 작고 한 목적에 집중하게 만들며, 병합 전 충돌과 Unity Console 오류를 확인합니다.
