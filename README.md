# 둘기의 도시 생존기

Unity C#으로 만드는 2D 모바일 사이드뷰 횡스크롤 서바이벌 액션 아케이드 게임입니다. 마리오처럼 옆에서 보는 평면 시점으로 도시를 이동하며 음식을 모으고, 동료 비둘기와 포섭한 인간의 수를 활용해 일반 잡몹을 상대합니다.

## 게임 방향

- 카메라는 탑뷰나 쿼터뷰가 아닌 2D 사이드뷰 횡스크롤입니다.
- 적은 상인, 어린이, 행인 등 일반 잡몹으로 구성하며 보스 캐릭터와 보스전은 두지 않습니다. 난이도는 잡몹의 이동·공격 패턴과 웨이브 밀도로 조절합니다.
- 동료 비둘기 수가 많을수록 응가 폭격 피해가 증가하고, 포섭한 인간 수가 많을수록 눈빛 공격 피해가 증가합니다. 증가 계수는 밸런스 데이터에서 조정합니다.
- 미니맵은 제공하지 않습니다. HUD에는 체력, 동료 비둘기 수, 포섭한 인간 수, 두 스킬의 상태를 표시합니다.

## 개발 환경

- Unity **6.0 이상**을 사용합니다. 패치 버전까지 팀원끼리 맞출 필요는 없습니다. `ProjectSettings/ProjectVersion.txt`는 프로젝트를 마지막으로 저장한 에디터 버전을 Unity가 기록하는 파일입니다.
- Git으로 프로젝트 전체를 공유합니다. `Library/`, 빌드 결과, 사용자별 에디터 설정은 저장소에 올리지 않습니다.
- 기본 에셋은 Unity 내장 기능만 사용합니다. 새 패키지를 추가할 때는 팀에 공유하고 `Packages/manifest.json`과 `Packages/packages-lock.json`을 함께 커밋합니다.

## 처음 실행하기

1. Unity Hub에서 Unity **6.0 이상**을 설치하고 사용할 플랫폼에 필요한 모듈을 선택합니다.
2. 저장소를 내려받은 뒤 Unity Hub의 **Add → Add project from disk**에서 저장소 폴더를 선택합니다.
3. 설치한 Unity 에디터로 프로젝트를 열고 패키지 가져오기가 끝날 때까지 기다립니다.
4. Unity 에디터에서 첫 씬을 만들고 사용할 플랫폼의 Build Profile에 추가합니다.

## 프로젝트 폴더

`Assets/_Project/` 아래 파일을 기능별로 나눕니다.

| 폴더 | 용도 |
| --- | --- |
| `Art/Characters` | 플레이어, 동료 비둘기, 일반 인간 잡몹 스프라이트 |
| `Art/Environment` | 음식, 오브젝트, 횡스크롤 배경과 지면·플랫폼 타일 |
| `Art/UI` | HUD 이미지와 스킬·인원 카운터 아이콘 |
| `Art/VFX` | 눈빛 공격과 응가 폭격 효과 |
| `Audio/SFX`, `Audio/BGM` | 효과음과 배경음 |
| `Data` | 음식, 일반 잡몹, 스테이지와 밸런스 ScriptableObject |
| `Prefabs`, `Scenes`, `UI` | 재사용 프리팹, 씬, UI |
| `Scripts/Core`, `Player`, `AI`, `Combat`, `UI` | 공통, 플레이어, AI, 전투, UI 코드 |

Unity 에디터에서 첫 씬과 플랫폼별 Player Settings를 설정한 뒤 씬을 Build Profiles에 추가하세요. 모바일 화면은 가로형 16:9을 기본으로 하고 19:20 비율에서도 플레이어와 진행 방향이 잘 보이도록 카메라와 HUD를 조정합니다.

## 브랜치와 병합 흐름

각 팀원은 본인 이름을 사용한 장기 브랜치를 직접 만들고(예: `team/<이름>`), 프로젝트가 완료될 때까지 유지합니다. `main`에는 직접 커밋하지 않고 각자 브랜치에서 개발합니다. `main`으로 보내는 Pull Request는 동아리 세션 시간의 팀 회의에서 함께 열고, 변경 내용을 검토한 뒤 병합합니다. 세션 전에는 완료된 작업도 본인 브랜치에 보관하고, `main` PR과 병합은 회의에서 진행합니다. 병합 뒤에도 팀원 브랜치는 프로젝트 완료 때까지 삭제하지 않습니다.

작업 전에는 최신 `main`을 본인 브랜치에 반영하고, PR에는 변경 목적과 확인한 내용, 씬·에셋 변경 사항을 적습니다. Unity의 `.meta` 파일은 에셋과 함께 커밋하고 삭제하거나 재생성하지 마세요. 프로젝트 완료 시 브랜치 정리는 팀과 함께 결정합니다.
